# Карта зрелости бизнес-решений

Самодиагностика команды бизнес-решений на 1С: опросник показывает текущий этап зрелости процесса разработки, путь до выбранной цели и ориентировочные сроки по шагам дорожной карты.

Страница: https://german09.github.io/business-maturity/

## Этапы

| Этап | Суть |
|---|---|
| 0 · Ручной режим | Правки в рабочей базе, задачи в почте, знания в головах |
| 1 · Базовые инструменты | Задачи в трекере, база знаний, хранилище или Git |
| 2 · Правила | Базы из шаблона, общий тестовый контур, правила выпуска |
| 3 · EDT и Git | Код в Git, команда поэтапно переходит в EDT |
| 4 · Конвейер | Сборка, проверки, доставка и защищённая выкладка |
| 5 · Контроль качества | Ревью, автотесты, приёмка и авторегистрация ошибок |
| 6 · ИИ в разработке и поддержке | Меньше затрат: ИИ пишет код и разбирает текущие данные |
| 7 · ИИ у пользователей | Руководители работают с данными через ИИ, меньше заказов на лишние отчёты |

## Как считается

- У каждой практики есть вес — её доля в общей зрелости, сумма весов 100.
- Обычная практика оценивается ползунком 0–100%, пошаговая — последним выполненным шагом.
- Практика или отдельный шаг блокируются, пока не выполнены практики, на которые они опираются.
- Этап засчитан, когда набрано не меньше 75% его баллов и все предыдущие этапы достигнуты.
- Сроки шагов зависят от трудозатрат команды в часах в месяц и от того, какие роли в ней закрыты отдельным человеком, а какие кто-то совмещает.
- Ответы хранятся только в браузере (localStorage), на сервер ничего не отправляется.

## Устройство

Один файл `index.html` без сборки: разметка, стили и скрипт внутри. Шрифты подключаются из Google Fonts. Модель зрелости — массивы `LEVELS` и `QS` в начале скрипта.

Публикуется через GitHub Pages из ветки `main`, корень репозитория.
